# Bulls and Cows (멀티플레이어 숫자 야구)

언리얼 엔진 5(Unreal Engine 5)의 멀티플레이어 프레임워크를 기반으로 제작된 1:1 온라인 숫자 야구(Bulls and Cows) 게임입니다. 
클라이언트-서버(Client-Server) 아키텍처 중 가장 견고한 형태인 데디케이티드 서버(Dedicated Server) 방식을 적용하여, 클라이언트 간의 완벽한 턴 동기화 및 무결성 높은 게임 환경을 구현했습니다.

---

## 구현 과정에서 사용된 핵심 멀티플레이어 개념

이 프로젝트는 멀티플레이어 게임에서 발생할 수 있는 데이터 위변조, 네트워크 지연, 세션 단절 등의 문제를 해결하기 위해 다음과 같은 언리얼 엔진의 핵심 네트워크 개념을 활용하여 설계되었습니다.

### 1. 네트워크 모드 (NetMode) : 데디케이티드 서버 (Dedicated Server)
플레이어 중 한 명이 방장(호스트) 역할을 겸하는 구조를 배제하고, 그래픽 렌더링을 수행하지 않는 별도의 독립된 서버 컴퓨터(프로세스)가 방을 유지하는 데디케이티드 서버 구조를 채택했습니다.
* **적용 사례:** 모든 플레이어는 동등한 클라이언트 자격으로 중앙 서버에 접속합니다. 한 플레이어의 네트워크 연결이 끊어지더라도 서버나 다른 플레이어의 게임 환경에 영향을 주지 않으며, 서버 트래블 시에도 세션이 안전하게 유지됩니다.

### 2. 권한 통제 (NetRole & Authority)
클라이언트가 임의로 정답을 조작하거나 점수를 올리지 못하도록 철저한 권한(Authority) 분리를 적용했습니다.
* **HasAuthority() (서버 권한):** 정답 번호 생성, 점수 판정, 타이머 관리, 턴 진행 통제는 오직 데디케이티드 서버만이 절대적인 권한을 가집니다. (`GameMode`에서 전담)
* **Autonomous Proxy (로컬 클라이언트):** 플레이어는 오직 서버에게 "채팅을 쳤다", "로비로 돌아가자"는 '요청(Request)'만 보낼 수 있으며, 게임의 상태를 직접 변경할 수 없습니다.

### 3. 언리얼 멀티플레이어 클래스 프레임워크 활용
각 클래스의 네트워크 생명주기를 엄격하게 구분하여 로직을 설계했습니다.
* **`AGameModeBase` (서버 전용):** 게임의 절대적인 규칙 통제. 플레이어 접속(`PostLogin`), 난수 정답 생성, 턴 진행 상태 검증, 라운드 초기화 및 승자 판정을 담당합니다. 이 클래스는 클라이언트 메모리에 존재하지 않습니다.
* **`APlayerState` (동기화 데이터):** 모든 클라이언트가 공유해야 하는 정보 보관. 각 유저의 현재 점수(`PlayerScore`), 남은 기회(`CurrentGuessCount`), 이번 턴 입력 완료 여부(`bHasActedThisTurn`)를 담아 데디케이티드 서버와 모든 클라이언트 간의 상태를 일치시킵니다.
* **`APlayerController` (통신 다리):** UI에서 입력된 유저의 행동을 서버로 전달(RPC)하고, 서버의 응답을 받아 로컬 UI를 업데이트하는 브릿지 역할을 수행합니다.

### 4. RPC (Remote Procedure Call) 구조
서버와 클라이언트 간의 원격 통신을 위해 2-Way RPC 시스템을 구축했습니다.
* **Client To Server (요청):** `Server_SendChatMessage`, `Server_RequestReturnToTitle`
  * 유저가 UI 버튼을 누르거나 채팅을 치면, 클라이언트 컨트롤러가 데디케이티드 서버에 존재하는 본인의 컨트롤러 함수를 호출하여 검증을 요구합니다.
* **Server To Client (응답 및 명령):** `Client_ReceiveChatMessage`, `ClientRPCShowEndGameUserWidget`
  * 서버에서 정답을 판정하거나 턴이 종료되면, 각 클라이언트의 컨트롤러에 명령을 내려 UI를 갱신하거나 결과 화면을 띄우도록 지시합니다.

### 5. 프로퍼티 레플리케이션 (Property Replication)
항상 일치해야 하는 중요한 변수들은 RPC 대신 언리얼의 자체 동기화 엔진인 레플리케이션을 사용했습니다.
* **적용 사례:** `DOREPLIFETIME` 매크로를 사용하여 `PlayerScore`와 `NotificationText` 변수가 서버에서 변경될 때마다 모든 클라이언트에게 자동으로 갱신되도록 처리하여 불필요한 네트워크 트래픽을 최소화했습니다.

### 6. 지연 초기화 (Lazy Initialization)를 통한 UI 생명주기 관리
심리스 트래블 과정에서 맵(`UWorld`)이 파괴될 때 위젯 인스턴스가 쓰레기 수집(Garbage Collection)되어 메모리 에러가 발생하는 언리얼 엔진 특유의 문제를 해결했습니다.
* **적용 사례:** `BeginPlay`에 의존하지 않고, 서버에서 UI 업데이트 명령이 내려올 때마다 위젯의 유효성을 검사하여 파괴되었을 경우 즉각 재생성하는 `GetOrCreateInGameUI()` 지연 초기화 패턴을 적용했습니다. 이를 통해 맵 이동을 무한히 반복해도 크래시 없는 안정적인 뷰포트를 구축했습니다.

## 주요 기능 (Features)
* **핑퐁 턴제 시스템 (Turn-Synchronization):** `bHasActedThisTurn` 변수와 마지막 입력자 추적 포인터를 활용하여 한 플레이어가 연속으로 입력할 수 없도록 강제하고, 공평한 턴제 진행을 보장합니다.
* **입력값 필터링:** 숫자가 아닌 순수 문자열 채팅과, 1~9 사이의 중복 없는 3자리 숫자(예측값)를 완벽히 분류하여 처리합니다.
* **상태 머신(State Machine) 타이머:** `EMatchState`(Waiting, Playing, Ending)에 따라 타이머의 역할을 동적으로 변환하여 하나의 루프 안에서 대기, 플레이 타임아웃, 결과 화면 대기 로직을 중앙 서버가 통제합니다.
